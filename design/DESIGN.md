# 控制台 UI 重构设计

历史场记先报账：设计与本地实现已获用户确认；2026-09-20 已推送 `ui/dashboard-redesign` 分支并部署到 OVH，部署验证见 `VALIDATION.md`。

## 设计方向

美术照用户提供的 CPA / CPA Keeper 截图搭台，不凭空开一间彩灯铺：白色背景、灰绿细边框、低饱和状态色、深色主按钮、下划线标签页和宽松表格行距。账号与模型二维矩阵照留；别家戏班的单模型数据结构与功能不来客串。

- 概览先摆主桌：模板就绪度、探测运行状态、注入策略、出口数量、模板矩阵、决策计数、探测活动。
- 探测范围点名入场：账号和模型选择、自定义模型、保存与放弃改动。
- 代理池安排领路人：静态与轮换入口编辑、追加、连通性检查及结果。
- 运行设置管后台开关：模拟运行、角色切换、只读参数、连通性自检、全部模板清理。

技术参数去设置与展开说明里候场，不挤在台口抢戏；保留影响操作决策的提示。首页不再让大段原理独占麦克风。颜色负责举牌,文字负责说清含义,不能只靠红绿脸让人猜。宽屏下双列编辑，窄屏单列；矩阵在卡片内横向滚动。

## 预览

开预览不必敲锣,用浏览器直接打开 `preview.html`。账号、地址、统计和活动全由假演员出演,均为虚构数据，不读取截图中的真实代理凭据，不连接线上接口。标签切换、选择、追加、确认弹窗和启停状态用于演示；保存、放弃、自检和测试结果都只是在走戏,不是正式功能实现。

预览的定妆照：`overview.png`、`proxies.png`、`mobile.png`。

## 正式实施的兼容约束

正式动刀只在这一张桌上：以 `go/ui.html` 为边界，保留现有接口、请求参数、数据流、轮询与业务决策。后端 Go、存储格式及调度规则不在本次 UI 改造的演员名单里。

| 现有功能 / 状态 | 新位置 | 保留要求 |
|---|---|---|
| `freshness`、`btnPause` | 顶栏 | 刷新按原钟点敲锣；原间隔、暂停恢复、陈旧与失败提示照留 |
| `badges` | 概览摘要 / 运行设置 | 原字段一个不少；没数据就认空桌，不冒充正常营业 |
| `notices` | 标签页外的全局消息区域 | 错误、操作反馈与复制信息照报，不藏进后台 |
| `scopeAccounts`、`scopeModels`、`scopeModelAdd` | 探测范围 | 账号 / 模型原名牌、停用标记、缺失项与动态选项照旧点名 |
| `scopeProxies`、`scopeRotating` 与追加输入 | 代理池 | 原始 URL 仍可编辑；顺序与去重守旧规矩，不擅给凭据蒙面 |
| `btnScopeSave`、`btnScopeReset` | 范围编辑区域 | 共用原 `scope` 草稿与 diff；切换标签不撕草稿，轮询也不能抢笔覆盖 |
| 范围和代理的保存入口 | 两个编辑页可访问 | 先说明这一笔要保存全部未保存改动，不能藏着点菜，复用既有确认和提交函数，不将未修改字段作为空列表提交 |
| `scopeErrors`、`scopeDirty` | 对应编辑页 / 全局提示 | 校验失败、脏状态、未保存项计数一直亮牌，不躲后台 |
| `btnProxyCheck`、`proxyCheck` | 代理池 | 检查只认已保存配置；结果、错误、出口分组和采样细节完整记账 |
| `summary`、`matrix` | 概览 | 选择范围内外的行列、额外模板、就绪分母、到期状态按原算盘计算 |
| 矩阵单桶清理 / 角标自检 | 概览矩阵 | 保持原点击含义与确认；空桶不许假装有货清理，但仍可自检；触屏与键盘入口可达 |
| `counters`、`since` | 概览 | 原统计字段、重置时间、空值处理；不凭空给账本加一桌客人 |
| `btnProbeStart`、`btnProbeCancel`、`probeProgress`、`probeLines` | 概览 | 保留忙状态、按钮禁用、原始日志及任务错误，不假装结构化日志接口已经来上班 |
| `btnDryRun`、`btnRole`、`btnClearAll` | 运行设置 | 确认内容、输入要求、请求参数及成功后刷新，全按原戏单 |
| `selftestAuth`、`selftestModel`、`btnSelftest` | 运行设置 | 定向参数、配额提示、结果和错误反馈照旧报账 |
| `modal` 及其子元素 | 全局弹窗 | 确认 / 取消 / 输入流程与键盘交互不换招式 |
| 暗色模式 | 全页面 | 沿用系统配色这件外套，补齐中性色与状态色，不只把灯关掉 |

别把参考项目的“停止当前轮”“按模型暂停”“预备接班槽”等现有项目未实现的操作请进正式页面冒充已会的本领。

## 实施及验证顺序

1. 先定戏路，再动布景：确认此设计方向，调整正式页面 DOM 分组与 CSS，保留既有元素 ID 和事件绑定。
2. 标签页只负责拉帘,不偷偷搬厨房。新增摘要从既有状态数据派生，更新显示不改变请求和后台行为。
3. 请假演员在本地对戏,用虚构接口响应验证原页面与新页面关键操作的请求路径、参数和确认结果一致。
4. 验收名单逐个点名：覆盖加载、空范围、空桶、范围外模板、过期、轮询失败、保存失败、未保存草稿、启停与取消、自检、清理、代理编辑和检查结果。
5. 大舞台小舞台都得站得稳：检查桌面 / 窄屏、暗色、键盘与控制台错误，运行项目相关回归测试。
6. 把本地可运行版本交到用户手里验戏。没等用户明确点头,不推送、不合并、不部署,锣鼓再响也不开演。

## 当前验证记录

- Chrome 桌面预览：四个标签页能轮流上台，确认弹窗也允许谢绝；探测启停演示正确更新状态。
- 390px 窄屏：四个页面都没挤出页面边界；矩阵只在自家容器内走动。
- 控制台没报错误或警告，页面也没偷偷出门请求网络资源。
- 以上是初版设计预览的旧场记,不是新一轮测试收据。正式实现的验证结果见 `VALIDATION.md`。
